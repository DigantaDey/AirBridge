Install with one command

macOS & Linux — installs the app and the AirBridge command, no sudo:

curl -fsSL https://raw.githubusercontent.com/DigantaDey/AirBridge/main/install.sh | bash

Windows PowerShell — user-scope install into %LOCALAPPDATA%\AirBridge:

powershell -ExecutionPolicy Bypass -Command "iwr https://raw.githubusercontent.com/DigantaDey/AirBridge/main/install.ps1 -UseBasicParsing | iex"

Both installers download over HTTPS and check the file against the release’s SHA256SUMS.txt before anything runs. Add --autostart (or -Autostart on Windows) to start AirBridge at login.

Stable releases vs development builds

  • Stable: the latest GitHub release (tagged v2.5.0 today). This is what the installers and the desktop self-updater use. Updates reach computers gradually — 10%, 50%, then 100% — and a bad release can be paused.
  • Development: builds from main and CI workflow artefacts. Useful for testing a fix, not for a machine you rely on. Build one yourself with npm ci && npm run build:desktop.
  • Android: the published APK is an installable testing/sideload build produced by the release workflow. The Play-ready App Bundle is a separate, signed upload path gated on a private key — see docs/PLAY_STORE_RELEASE.md. No unsigned substitute is ever published as a “release”.

Verify what you downloaded

Every release includes SHA256SUMS.txt and keyless Sigstore build-provenance attestations:

sha256sum --check SHA256SUMS.txt
gh attestation verify AirBridge-linux-x64 -R DigantaDey/AirBridge

The macOS and Windows binaries are not signed with paid vendor certificates: the macOS app is ad-hoc signed (so Apple silicon will run it) and the Windows EXE is unsigned. Checksums, attestations and the self-updater’s own verification are the integrity story, and they are documented in docs/DISTRIBUTION.md.

Requirements and ports

  • Android 8.0 (API 26) or newer for the phone app.
  • macOS with Apple silicon or Intel, Windows x64 or ARM64, or Linux x64/arm64 on glibc or musl. Prebuilt binaries need no Node.js.
  • Building from source needs Node.js 20+, npm and Git; Android builds need JDK 17, Gradle and Android SDK 35.
  • Network: phone and computer on the same Wi-Fi (or the phone’s hotspot). The service listens on port 3000 by default — set PORT to change it, and allow the app through the Windows firewall for private networks.

Questions about this guide

Which macOS file should I download on an Apple silicon Mac?＋

AirBridge-macOS-arm64.zip (or AirBridge-darwin-arm64 for the bare binary). Use the x64 files on Intel Macs. The install.sh script picks the right build automatically.

Do I need Node.js to run AirBridge?＋

No. The macOS app, Windows EXE and Linux binaries embed everything. Node.js 20+ is only needed to build from source or to use npx airbridge.

Why is AirBridge not on the App Store or the Microsoft Store?＋

Store distribution needs paid developer accounts. AirBridge distributes ad-hoc signed macOS builds and unsigned Windows executables from GitHub instead, and publishes checksums plus Sigstore attestations so you can verify them.

Is the Android APK a Play Store build?＋

It is an installable testing/sideload build produced by the release workflow. The Play-ready App Bundle is built separately and fails closed unless a private upload key is configured, as documented in docs/PLAY_STORE_RELEASE.md.
