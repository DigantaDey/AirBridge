GUIDE PRIVACY & SECURITY

Private file transfer between your phone and your computer

A private transfer means three things at once: the content is encrypted end to end, no third party keeps a copy, and you are told honestly what can still be observed. AirBridge is designed around all three, so this page lists both the protections and the limits.

The model, in plain terms

  • No account. There is nothing to sign up for, no identity server, and no device directory outside your own network.
  • No cloud copy. Files are streamed between the two devices. The only optional server is a relay you can run yourself, and it forwards ciphertext.
  • End-to-end encryption. Pairing is proven with SPAKE2 (RFC 9382); session keys come from ephemeral ECDH P-256 with HKDF; file chunks, clipboard items, call audio and screen frames are sealed with AES-256-GCM.
  • Verified before saved. A received file is published only when its SHA-256 digest matches what the sender declared.
  • No analytics in the app. The Android app contains no advertising or analytics SDK, and the marketing site is a static page with no tracking scripts.

What an observer can still see

Honest privacy writing names the gaps. Before pairing, devices on the same network can see that an AirBridge device exists, its device name and its public key — discovery is not trust. The network operator (or anyone who can watch the link) can see addresses, ports, timing and rough volume, even though the payload is ciphertext. A relay sees connection metadata and ciphertext, never session keys.

The pairing code itself is never transmitted, not even as a hash, and pairing attempts are rate-limited, so guessing the code is not a practical way in. A six-digit SAS code and a pinned TLS certificate authority let you detect a substituted key on first contact.

The computer is a separate trust boundary

The desktop service exposes host-level actions — writing the system clipboard, saving into the receive folder, revealing a file, opening a folder — only on loopback. A paired phone cannot ask your computer to run a shell command. Folder-open requests are constrained to the configured receive folder and use a fixed argument vector, not a shell.

On the Android side, the app declares no Accessibility service and no notification listener, requests no call-log permission, and disables Android backup so pairing state and TLS pins stay on the device. Every continuity permission — contacts, phone, microphone, screen capture — is off until you enable that specific feature.

Diagnostics, crash reports and what leaves your device

Diagnostics stay local. Bundles are bounded, and personal data is redacted — home paths and usernames, IP and MAC addresses, Wi-Fi SSIDs, pairing codes, tokens and cryptographic keys. Nothing is uploaded automatically: a report is only shared when you review it and click Copy diagnostics, Report on GitHub or Send report. The privacy policy lists this in the same detail.

Limits and disclosures

  • No independent audit. The project publishes its own threat model and audit notes in SECURITY.md; it does not claim a third-party audit or absolute-security guarantees.
  • Ad-hoc signed macOS binaries and unsigned Windows binaries mean Gatekeeper and SmartScreen friction; integrity comes from published checksums and Sigstore attestations rather than paid certificates.
  • Screen sharing respects DRM and stays blank for protected content, and call audio routing uses an opt-in, speakerphone-assisted bridge because unrooted Android restricts raw cellular uplink injection.
  • Local threats remain. A compromised device, malware with screen access, or someone who can read your unlocked phone are outside any app’s threat model.

Verify a release, verify a device

gh attestation verify AirBridge-macOS-arm64.zip -R DigantaDey/AirBridge

For the device side: compare the six-digit verification code on first pairing, keep an eye on the trusted-device list, and use Forget on the phone if a pinned certificate ever changes unexpectedly. A TLS error is never permission to downgrade to plaintext.

Questions about this guide

Does AirBridge store my files anywhere?＋

No. Files are streamed between the paired devices and written to the receive folder you configured. There is no AirBridge account or storage service.

Does the relay see file contents?＋

No. The relay forwards ciphertext inside an end-to-end TLS session that stays pinned between the devices. It can observe connection metadata such as addresses and timing, as any network hop can.

Is there telemetry or analytics?＋

The Android app ships no advertising or analytics SDK, and the static website does not load tracking scripts. Diagnostics are generated locally and only shared when you click a share action.

Has AirBridge been audited by a third party?＋

No. The maintainer publishes the threat model and audit notes in SECURITY.md, and the cryptographic primitives are audited libraries, but there is no independent third-party audit and the site does not claim one.
