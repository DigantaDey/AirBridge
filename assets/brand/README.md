# AirBridge brand assets

The brand set, extracted from the brand sheet (the single composite image the
artwork shipped as). Every variant in the sheet has one home in the product:

| Sheet variant | Source here | Used as |
| --- | --- | --- |
| Colour gradient mark | `mark.png` | favicon, in-app logo, OG card, Android vector |
| "AirBridge" wordmark | `wordmark.png` | OG card (SVG lockups use `<text>`) |
| Black monochrome lockup | `lockup-mono.svg` | docs / print / one-colour contexts |
| Dark rounded-tile app icon | generated | `public/icon.svg`, `website/icon.svg`, `website/favicon-32.png`, `website/apple-touch-icon.png`, `macos/AirBridge.icns`, Android launcher |
| Gradient mark at small sizes | generated | favicon + in-app logo (36 px) |

## Palette

Sampled from the sheet artwork:

- Tile navy `#0F1222` — app-tile background, Android launcher background.
- Mark gradient (top-left → bottom-right): `#7239e2` → `#4227bb` →
  `#1f3fbd` → `#178fcb` → `#6fe7df`.
- Wordmark / monochrome ink `#111111`.

## Regenerating

The raster sources (`mark.png`, `wordmark.png`) are committed. Everything else
is generated by one script:

```bash
npm run brand:assets
```

It traces the mark's outline from its alpha channel
(`scripts/brand/trace-mark.mjs`, marching squares + RDP simplification),
self-checks the trace by re-rasterising it (fails below 98% IoU), and rewrites
the SVGs, PNGs, the macOS `.icns`, the Android vector icon and the in-app logo
path module (`src/client/components/brandMarkPath.ts`). It needs ImageMagick
on the maintainer machine; CI never runs it — the outputs are committed and
guarded by `tests/brand-assets.test.ts`.

To change the brand, replace the two source PNGs and re-run the script. Do not
hand-edit the generated files.
